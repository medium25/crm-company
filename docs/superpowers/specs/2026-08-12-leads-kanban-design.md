# Заявки: единая kanban-доска вместо двух списков

## Проблема

`LeadsPage.jsx` — два независимых грида рядом («Записи»: 4 стадии,
«Результаты»: 2 исхода). Перенос лида между стадиями — только через
выпадающее меню на 3 точки (пункт «Перенести: ...» на каждый вариант, плюс
отдельно «Пришли»/«Не пришли»/«Вернуть в работу»). Неудобно: чтобы подвинуть
лида на день, нужно открыть меню и найти нужный пункт среди списка. На
карточке не видно, чей это лид — только имя и телефон самого лида.

Оператор работает с окном каждый день, счёт лидов — 15-25 в день. Ресёрч по
top CRM для колл-центров (Pipedrive, Close, Dynamics 365 — см. обсуждение)
сходится на одном паттерне: kanban-доска с drag-n-drop между стадиями одним
движением, цветной аватар/акцент владельца на карточке, компактная, но
насыщенная карточка без вложенных меню для частых действий.

## Что меняется

### Layout

Два грида объединяются в одну kanban-доску — одна строка, 6 колонок,
горизонтальный скролл на узких экранах:

```
Сегодня | Завтра | След. неделя | Позже | Пришли | Не пришли
```

Первые 4 = `leadStage` (как сейчас, `STAGE_ORDER`), последние 2 =
`leadResult` (как сейчас). Карточка живёт в первой ветке, если
`!lead.leadResult`, во второй — если `leadResult` проставлен (та же логика
разделения, что в текущих `byStage`/`byResult`, просто в одном ряду колонок
вместо двух отдельных гридов).

Заголовок колонки не меняется: название + счётчик + кнопка «+» (добавить
лида сразу в эту колонку — переиспользует существующий `openAddForm`).

### Перенос между колонками — 2 механизма параллельно

**Drag-n-drop (десктоп/мышь).** Нативный HTML5 DnD, без новых зависимостей:
`draggable` на карточке, `onDragOver`/`onDrop` на колонке. Никакого
отдельного «оптимистичного» состояния не заводим — `useCollection`
подписан на `onSnapshot`, а Firestore SDK по умолчанию сразу отражает
локальную запись в снепшоте до подтверждения сервера, так что карточка
переезжает в момент drop без ручного стейта.

**Кнопка «→» (телефон/тачскрин + быстрая альтернатива на десктопе).**
Маленькая кнопка на карточке, всегда видна. Клик открывает компактное меню
из 6 колонок (переиспользует `DropdownMenu`) — тап вместо драга. HTML5 DnD
не работает на тачскринах, `draggable` там просто ничего не делает, так что
одновременное существование обоих механизмов ничего не ломает.

**Единая функция переноса** (заменяет `onSetStage`/`onSetResult`/
`onReturnToWork`):

```js
function moveLead(lead, columnKey) {
  if (STAGE_ORDER.includes(columnKey)) {
    patch(lead, { leadStage: columnKey, leadResult: null });
  } else {
    patch(lead, { leadResult: columnKey }); // 'came' | 'not_came'
  }
}
```

Если `columnKey` совпадает с текущей колонкой лида — no-op, лишней записи в
Firestore не шлём.

### Карточка

- Аватар красится в цвет оператора (`staff.color` того, кто в
  `lead.createdBy`) вместо текущего серого `bg-surface-alt`. Имя оператора
  текстом на карточку не добавляем (решили — цвета достаточно), но
  `title="{имя оператора}"` на аватаре для tooltip при наведении — бесплатно,
  никакого лишнего текста в вёрстке.
- Кнопка «Позвонить» (иконка ☎, `onCall`) переезжает из выпадающего меню на
  саму карточку — самое частое действие в колл-центре не должно быть
  спрятано за меню.
- Кнопка «→» (описана выше) — рядом с «Позвонить».
- Меню «...» худеет до 3 пунктов: «Записать на пробный» (только для
  `status === 'lead'`), «Редактировать», «Отказ». Пункты переноса
  («Перенести: ...», «Пришли», «Не пришли», «Вернуть в работу») убираются —
  их полностью заменяют drag и кнопка «→».

### Цвет оператора — новое поле `staff/{uid}.color`

Тот же паттерн, что уже есть у курсов (`CoursesPage.jsx`, константа
`PALETTE` + кружки-свотчи, выбор при редактировании, хранится как hex-строка
на документе). Переиспользуем ту же 6-цветную `PALETTE` (сейчас 3
сотрудника с ролью ceo/manager/admin — с запасом хватает, при росте команды
просто расширим массив). Добавляется колонка «Цвет» в
`StaffSettingsTab.jsx` — та же палитра-пикер, обновляет `staff/{uid}.color`
через `updateDoc`. Права не меняются: `staff` уже пишется/читается только
`isAdmin()` (ceo/manager/admin — те же роли, что работают с заявками).

Дефолт для сотрудников без выбранного цвета — нейтральный серый
(`bg-surface-alt`, как сейчас), чтобы не ломать существующие карточки до
того, как админ пройдётся по настройкам и расставит цвета.

## Данные

Новых коллекций нет. Новое поле: `staff/{uid}.color: string | null` (hex,
`#RRGGBB`). `leadStage`/`leadResult` — без изменений в схеме, меняется
только откуда пишутся (drag/кнопка вместо пунктов меню).

## Не входит в эту итерацию

- Поиск/фильтр по оператору или имени — не просили, при необходимости
  добавим отдельно поверх готовой доски.
- Кастомный drag на Pointer Events для тачскринов (плавный drag пальцем) —
  вместо этого кнопка «→», дешевле и работает везде одинаково.
- Легенда «кто есть кто» по цветам — только tooltip на аватаре.
- Изменение прав доступа к `staff` — уже достаточно широкие для нужных ролей.
