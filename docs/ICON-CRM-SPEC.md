# ICON CRM — полное техническое задание

CRM для учебного центра ICON Education (Ташкент): языковые курсы, группы,
посещаемость, оплаты, балансы студентов. Документ реконструирован по 6 скриншотам
референсной системы и рассчитан на то, чтобы его целиком отдать агенту
(Claude Code / Codex) и получить работающий продукт без дополнительных объяснений.

Всё, чего не видно на скриншотах, помечено в тексте как **[достроено]** —
это предложение, а не реконструкция. Ссылки вида **[реф. скрин N]** указывают на
исходные скриншоты; держи их рядом, документ их дополняет, а не заменяет.

## Как этим пользоваться

**Claude Code.** Положи этот файл в корень пустого репозитория как `CLAUDE.md`,
скриншоты — в `docs/reference/`. Запусти агента и скажи:
`Прочитай CLAUDE.md целиком. Дальше работаем строго по разделу «План разработки».`

**Codex.** Тот же файл, но в корне репозитория под именем `AGENTS.md`.

Дальше идёшь по фазам из раздела «Промпты по фазам» — по одной фазе за сессию.
Не запускай фазу N+1, пока не закрыты критерии приёмки фазы N. В конце каждой фазы
проси обновить `docs/PROGRESS.md` — это спасает контекст между сессиями.

## 00 · Контекст проекта и правила работы

CRM для учебного центра ICON Education (Ташкент): языковые курсы, группы,
посещаемость, оплаты, балансы студентов.

Полное ТЗ — ниже в этом же файле. Визуальный эталон — скриншоты в `docs/reference/`.
Читай этот файл целиком перед любой задачей. Если задача ему противоречит — останавливайся
и спрашивай, не додумывай.

### Стек

- **React 18 + Vite**, JavaScript (JSX). TypeScript не используем.
- **Tailwind CSS** — токены заданы в `tailwind.config.js` (см. «05 · Дизайн-система»).
- **React Router v6**, `HashRouter` (обязательно — деплой на GitHub Pages).
- **Firebase**: Auth (email+password), Firestore, Storage (аватары).
- **date-fns** + локаль `ru` — единственная библиотека для дат.
- **Recharts** — графики.
- **lucide-react** — иконки.
- Деплой: GitHub Pages через `gh-pages`.

Не добавляй новые зависимости без явного разрешения. Redux, MUI, Ant Design,
styled-components, Zustand — запрещены.

### Структура

```
src/
  main.jsx
  App.jsx                    роутинг + провайдеры
  firebase.js                init, экспорт db/auth/storage
  types.js                   JSDoc-typedef всех сущностей (единый источник правды)
  lib/
    format.js                деньги, телефоны, даты, склонения
    schedule.js              генерация уроков из расписания группы
    billing.js               списания, баланс, price per lesson
    stats.js                 KPI дашборда
  hooks/
    useAuth.js  useCollection.js  useDoc.js  useRole.js
  components/
    ui/                      Button, Card, Input, Select, Modal, Badge, Tabs,
                             Table, DatePicker, Toast, ConfirmDialog, EmptyState
    layout/                  Sidebar, Topbar, PageHeader, FilterBar
  features/
    dashboard/ students/ leads/ groups/ teachers/ courses/ rooms/
    attendance/ payments/ reports/ settings/
  pages/                     по одному файлу на маршрут
docs/
```

Один компонент — один файл. Файл больше 300 строк — дробим.

### Правила данных

- **Деньги** — целые числа в сумах (`840000`), без копеек и без строк.
  Форматирование только через `formatMoney()` → `840 000 UZS` (неразрывный пробел).
- **Даты в базе** — Firestore `Timestamp`. В UI — `dd.MM.yyyy`. Месяц-период — строка `"2026-07"`.
- **Телефон** — в базе `998901234567` (только цифры), в UI `90 123 45 67`.
- **Удаление — мягкое.** `isArchived: true`, никогда не `deleteDoc()` для студентов,
  групп, платежей и списаний. Жёсткое удаление разрешено только для черновиков лидов.
- **Финансовые записи неизменяемы.** Ошибочный платёж не редактируется, а гасится
  сторно-записью (`type: 'correction'`).
- **Никаких выдуманных данных.** Нет данных — показывай `EmptyState`, а не заглушку
  с фейковыми студентами. Сид-данные только в `scripts/seed.js` и только по запросу.

### Правила кода

- Функциональные компоненты + хуки. Никаких классов.
- Данные грузим через `useCollection`/`useDoc` (обёртки над `onSnapshot`),
  запросы — с `where`/`limit`, без выгрузки коллекции целиком в память.
- Каждое состояние экрана обрабатывается явно: `loading` (скелетон),
  `error` (сообщение + кнопка «Повторить»), `empty` (EmptyState), `data`.
- Все тексты интерфейса — на русском, в коде — латиница.
- Любая мутация → toast с результатом. Любое разрушающее действие → `ConfirmDialog`.
- Роли проверяем и в UI, и в Firestore Rules. UI-проверка — не защита.

### Команды

```bash
npm run dev      # локальная разработка
npm run build    # сборка
npm run deploy   # gh-pages
npm run lint
```

### Definition of Done для любой задачи

1. Работает в браузере, консоль без ошибок и варнингов React.
2. Обработаны loading / error / empty.
3. Верстка не ломается на 1280px и на 390px (мобильные — минимум читаемость и скролл).
4. Firestore-запросы не тянут лишнего, нужные индексы добавлены в `firestore.indexes.json`.
5. `docs/PROGRESS.md` обновлён: что сделано, что осталось, где остановились.
6. Если менялась структура данных — обновлён «02 · Модель данных» и `src/types.js`.

### Чего не делать

- Не менять схему данных «по ходу дела» молча.
- Не заводить бэкенд/Cloud Functions — план Spark, всё считается на клиенте
  (см. раздел «Биллинг-ран» в «03 · Бизнес-логика»).
- Не рефакторить то, что не просили.
- Не оставлять `TODO` без записи в `docs/PROGRESS.md`.

## 01 · Обзор продукта

### Задача

Учебный центр ведёт студентов, группы, посещаемость и деньги. Сегодня эти данные
живут в чужой CRM. Цель — своя система, где администратор за один рабочий день
закрывает весь цикл: принял лид → записал на пробный → добавил в группу →
отметил посещаемость → принял оплату → увидел, кто должник.

### Кто пользуется

| Роль | Кто это | Что делает каждый день |
|---|---|---|
| `owner` | Владелец / CEO | Смотрит дашборд и финансы, заводит филиалы и сотрудников |
| `admin` | Администратор ресепшена | Лиды, студенты, группы, приём оплат, звонки |
| `teacher` | Учитель | Отмечает посещаемость и оценки в своих группах |
| `accountant` | Бухгалтер *(P1)* | Платежи, списания, сверка, выгрузки |

#### Матрица прав

| Действие | owner | admin | teacher | accountant |
|---|:--:|:--:|:--:|:--:|
| Дашборд (все KPI) | ✅ | ✅ | ❌ | ✅ |
| Лиды: создать / редактировать | ✅ | ✅ | ❌ | ❌ |
| Студенты: создать / редактировать | ✅ | ✅ | ❌ | ❌ |
| Студенты: смотреть | ✅ | ✅ | только своих групп | ✅ |
| Группы: создать / редактировать | ✅ | ✅ | ❌ | ❌ |
| Посещаемость: отмечать | ✅ | ✅ | только свои группы | ❌ |
| Оценки, экзамены | ✅ | ✅ | только свои группы | ❌ |
| Принять оплату | ✅ | ✅ | ❌ | ✅ |
| Сторно / ручное списание | ✅ | ❌ | ❌ | ✅ |
| Финансы: раздел целиком | ✅ | ограниченно¹ | ❌ | ✅ |
| Учителя, курсы, кабинеты | ✅ | ✅ | ❌ | ❌ |
| Сотрудники и роли | ✅ | ❌ | ❌ | ❌ |
| Настройки филиала | ✅ | ❌ | ❌ | ❌ |
| Запуск месячного биллинга | ✅ | ❌ | ❌ | ✅ |

¹ `admin` видит только платежи, которые провёл сам, и суммы по своему филиалу;
общую прибыль центра не видит.

Учитель никогда не видит: балансы, платежи, цены, телефоны студентов чужих групп.

### Мультифилиальность

Каждая сущность привязана к `branchId`. Пользователь имеет `branchIds: []` —
список доступных филиалов, и активный филиал переключается в топбаре.
`owner` видит все филиалы + сводный режим «Все филиалы».

На скриншотах филиал один — `ICON Education`. Модель данных закладывается
мультифилиальной сразу, потому что переезжать на неё потом дорого.

### Глоссарий

| Термин | Значение в системе |
|---|---|
| **Лид** | Контакт, который ещё не начал учиться. `student.status = 'lead'` |
| **Пробный урок** | Лид пришёл на одно занятие. `status = 'trial'` |
| **Студент** | Учится хотя бы в одной группе. `status = 'active'` |
| **Группа** | Код (`I14`, `R30`, `MINI 1`) + курс + учитель + расписание + кабинет |
| **Курс** | Программа: `INGLIZ TILI`, `RUS TILI` |
| **Запись** (enrollment) | Связка студент↔группа со своей ценой, статусом и датами |
| **Урок** | Одна конкретная дата занятия группы |
| **Посещаемость** | Отметка `Был` / `Нет` студента на уроке |
| **Списание** | Отрицательная финансовая запись за обучение (`charge`) |
| **Оплата** | Положительная финансовая запись (`payment`) |
| **Баланс** | Оплаты − списания. Отрицательный = долг |
| **Должник** | Студент с балансом < 0 |
| **Заморозка** | Пауза в записи: уроки не начисляются и не списываются |
| **Архив** | Мягко удалённая сущность: не в списках, но данные и история целы |

### Границы MVP

#### P0 — без этого не запускаемся
1. Авторизация и роли.
2. Справочники: филиалы, курсы, кабинеты, учителя, сотрудники.
3. Группы: список с фильтрами, карточка, расписание, состав.
4. Студенты и лиды: список, карточка, запись в группу, перевод между статусами.
5. Посещаемость по месяцам.
6. Деньги: приём оплаты, автосписание, баланс, список всех платежей с фильтрами.
7. Дашборд с 8 KPI и графиком выручки по месяцам.

#### P1 — сразу после запуска
Оценки, экзамены, комментарии и история изменений, скидки, SMS-шаблоны,
история звонков, импорт учителей/студентов из Excel, экспорт списков,
роль бухгалтера, отчёты (по учителям, по курсам, отток).

#### P2 — заложить в архитектуру, не строить
Монеты/рейтинг студентов (`Show coins` на скриншоте 4), онлайн-уроки и
материалы, воронка лидов канбаном, зарплаты учителей, Telegram-бот
уведомлений родителям, мобильное приложение учителя.

#### Non-goals — не делаем вообще
- Не строим LMS: видеоуроки, тесты, домашки внутри системы.
- Не строим бухгалтерию: НДС, акты, интеграция с 1С.
- Не подключаем платёжные шлюзы (Click/Payme) — оплата фиксируется вручную
  админом, метод оплаты указывается как поле.
- Не делаем офлайн-режим и синхронизацию.

### Метрики успеха

| Показатель | Цель |
|---|---|
| Приём оплаты | ≤ 20 секунд от открытия карточки до сохранения |
| Отметка посещаемости группы (6–10 чел) | ≤ 30 секунд |
| Баланс студента и данные CRM | расхождений 0 |
| Список групп (29 записей) с фильтрами | ≤ 1 сек до первой отрисовки |
| Обучение нового администратора | ≤ 1 час без инструкции |

### Открытые вопросы

| № | Вопрос | Кто отвечает | Блокирует |
|---|---|---|---|
| 1 | Иконка «призрак» в карточке студента (скрин 6) — это отчисление или скрытый статус? | Заказчик | Фаза 3 |
| 2 | ~~`lessonsPerMonth` = 14 — это константа центра или настройка курса?~~ Отвечено: база **12** уроков (840к/890к — цена за 12 уроков, 13-й/14-й в месяце — бонусные, без доплаты), задаётся в филиале, переопределяется на группе | Заказчик | Фаза 5 ✅ |
| 3 | «Неделя обучения» считать от даты старта группы или от даты входа студента? | Заказчик | Фаза 2 |
| 4 | Списание при пропуске урока — да или нет? (реф. система, судя по данным, списывает независимо от посещения) | Заказчик | Фаза 5 |
| 5 | Нужен ли учителю доступ в систему на старте или отметки ставит админ | Заказчик | Фаза 4 |

## 02 · Модель данных (Firestore)

Единый источник правды по структуре. При изменении схемы этот файл правится
первым, потом `src/types.js`, потом код.

### Общие соглашения

- Все документы имеют: `branchId` (string), `createdAt` (Timestamp),
  `createdBy` (uid), `updatedAt`, `updatedBy`.
- Мягкое удаление: `isArchived: boolean` + `archivedAt` + `archivedReason`.
- Деньги — целые числа в сумах: `840000`.
- Даты — `Timestamp`. Периоды-месяцы — строка `"2026-07"`. Дата урока дополнительно
  хранится строкой `dateKey: "2026-07-24"` для дешёвых запросов и группировок.
- Телефон — строка из цифр без плюса: `"998940189956"`.
- ID документов: авто, кроме случаев, где нужна идемпотентность (см. `transactions`).

---

### `branches` — филиалы

```js
{
  id: "icon-main",
  name: "ICON Education",
  address: "Ташкент, ...",
  phone: "998712000000",
  timezone: "Asia/Tashkent",
  currency: "UZS",
  lessonsPerMonth: 12,        // база для расчёта цены урока, см. 03
  isArchived: false
}
```

### `staff` — сотрудники (документ на каждого пользователя Auth)

ID документа = `uid` из Firebase Auth.

```js
{
  id: "uid_abc",
  fullName: "Mr Abduganiev",
  phone: "998901112233",
  email: "admin@icon.uz",
  role: "admin",              // owner | admin | teacher | accountant
  branchIds: ["icon-main"],
  teacherId: null,            // заполнен, если role === 'teacher'
  isActive: true
}
```

### `courses` — курсы

```js
{
  id: "ingliz-tili",
  name: "INGLIZ TILI",
  defaultPrice: 890000,       // цена в месяц по умолчанию
  defaultDurationMonths: 12,
  color: "#22406B",           // для меток в интерфейсе
  isArchived: false
}
```

Из скриншотов: `INGLIZ TILI`, `RUS TILI`.

### `rooms` — кабинеты

```js
{
  id: "room-4",
  branchId: "icon-main",
  name: "4",
  capacity: 12,               // «Вместимость комнаты» на скрине 4
  isArchived: false
}
```

### `teachers` — учителя

```js
{
  id: "t_sanjar",
  branchId: "icon-main",
  displayName: "MR SANJAR",   // именно так, как отображается в списках
  fullName: "Sanjar Karimov",
  phone: "998904020021",
  staffUid: null,             // если у учителя есть вход в систему
  branchIds: ["icon-main"],   // учитель может работать в нескольких филиалах
  groupsCount: 6,             // денормализовано, пересчитывается при CRUD группы
  isActive: true,
  isArchived: false
}
```

Со скриншота 2: MR SANJAR (6 групп), MS SHAXZODA (8), MS KAMILLA (0),
MS ZIYODA (BETA) (4), MS KRISTINA (11).

### `groups` — группы

```js
{
  id: "g_146270",
  branchId: "icon-main",
  code: "I14",                       // I12, I13, R30, MINI 1
  publicId: 146270,                  // «(id: 146270)» на скрине 4
  courseId: "ingliz-tili",
  courseName: "INGLIZ TILI",         // денорм. для таблиц
  teacherId: "t_sanjar",
  teacherName: "MR SANJAR",          // денорм.
  roomId: "room-4",
  roomName: "4",

  schedule: {
    type: "even",                    // even | odd | weekdays
    weekdays: [],                    // [1,3,5] если type === 'weekdays'
    time: "18:30",
    durationMin: 90
  },

  startDate: Timestamp,              // 01.11.2025
  endDate: Timestamp,                // 01.12.2026
  price: 890000,                     // цена группы в месяц
  lessonsPerMonth: 12,               // наследуется от филиала, можно переопределить
  tags: ["R30"],
  status: "active",                  // planned | active | finished | archived
  studentsCount: 6,                  // денорм.
  isArchived: false
}
```

**«Неделя обучения»** в таблице групп не хранится — вычисляется (см. `03`).

### `students` — студенты и лиды (одна коллекция)

```js
{
  id: "s_1658867",
  branchId: "icon-main",
  publicId: 1658867,                 // «(id: 1658867)» на скрине 6
  fullName: "Abduqodir Jo'raev",
  phone: "998940189956",
  phone2: null,
  birthDate: null,
  gender: null,
  photoUrl: null,

  status: "active",                  // lead | trial | active | paused | left | archived
  statusReason: null,                // причина ухода
  source: null,                      // instagram | telegram | друзья | наружная | другое

  balance: -140000,                  // денорм. агрегат, см. 03 «Пересчёт баланса»
  balanceUpdatedAt: Timestamp,

  note: "",                          // поле «Заметка» на скрине 6
  isFlagged: false,                  // флажок рядом с заметкой

  activeGroupsCount: 1,              // денорм.
  firstPaymentAt: Timestamp,
  lastPaymentAt: Timestamp,
  trialAt: null,                     // когда был пробный
  leftAt: null,

  createdAt: Timestamp,              // «Дата добавления: 24 июля 2026 г.»
  createdBy: "uid_abc",
  isArchived: false
}
```

Лид — тот же документ со `status: 'lead'`. Отдельной коллекции лидов нет:
конверсия лид→студент не должна терять историю звонков и комментариев.

### `enrollments` — записи студента в группу

Ключевая коллекция. Один документ = один студент в одной группе.

```js
{
  id: "e_xyz",
  branchId: "icon-main",
  studentId: "s_1658867",
  studentName: "Abduqodir Jo'raev",   // денорм.
  groupId: "g_r30",
  groupCode: "R30",                   // денорм.
  courseName: "RUS TILI",             // денорм.
  teacherId: "t_ziyoda",
```

### Security Rules (каркас)

```js
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {

    function staff()      { return get(/databases/$(db)/documents/staff/$(request.auth.uid)).data; }
    function role()       { return staff().role; }
    function branches()   { return staff().branchIds; }
    function inBranch(b)  { return b in branches(); }
    function isOwner()    { return role() == 'owner'; }
    function isAdmin()    { return role() in ['owner', 'admin']; }
    function isFinance()  { return role() in ['owner', 'accountant']; }
    function isTeacher()  { return role() == 'teacher'; }
    function teachesGroup(gid) {
      return isTeacher() &&
        get(/databases/$(db)/documents/groups/$(gid)).data.teacherId == staff().teacherId;
    }

    match /staff/{uid} {
      allow read: if request.auth.uid == uid || isOwner();
      allow write: if isOwner();
    }

    match /students/{id} {
      allow read:   if isAdmin() || isFinance() || isTeacher();
      allow create: if isAdmin() && inBranch(request.resource.data.branchId);
      allow update: if isAdmin() && inBranch(resource.data.branchId);
      allow delete: if false;                       // только мягкое удаление
    }

    match /groups/{id} {
      allow read:   if inBranch(resource.data.branchId);
      allow write:  if isAdmin() && inBranch(request.resource.data.branchId);
    }

    match /lessons/{id} {
      allow read:  if inBranch(resource.data.branchId);
      allow write: if isAdmin() || teachesGroup(request.resource.data.groupId);

      match /attendance/{studentId} {
        allow read:  if true;
        allow write: if isAdmin() ||
          teachesGroup(get(/databases/$(db)/documents/lessons/$(id)).data.groupId);
      }
    }

    match /transactions/{id} {
      allow read:   if isFinance() || isAdmin();
      allow create: if isFinance() || (isAdmin() && request.resource.data.type == 'payment');
      allow update, delete: if false;               // транзакции неизменяемы
    }

    match /enrollments/{id} {
      allow read:  if inBranch(resource.data.branchId);
      allow write: if isAdmin();
    }
  }
}
```

Учителю запрещено читать `transactions` — на уровне правил, не только в UI.

### Денормализация: что и когда пересчитывать

| Поле | Когда обновляется |
|---|---|
| `teachers.groupsCount` | создание / архивация / смена учителя у группы |
| `groups.studentsCount` | создание / архивация / смена статуса enrollment |
| `students.balance` | любая запись в `transactions` (в той же batch-операции) |
| `students.activeGroupsCount` | смена статуса enrollment |
| `monthlyBalances.*` | любая запись в `transactions` (той же batch) |

Все связанные обновления делаются через `writeBatch()` — не отдельными вызовами.

## 03 · Бизнес-логика и формулы

Всё, что здесь описано, выведено из чисел на скриншотах и проверено на них.
Проверки приведены прямо в тексте — если реализация даст другой результат,
значит реализация неверна.

---

### 1. Жизненный цикл студента

```
   [lead] ──записали на пробный──► [trial] ──добавили в группу──► [active]
      │                              │                              │
      │ отказ                        │ не пришёл / не купил         │ заморозка
      ▼                              ▼                              ▼
   [archived]                     [left]                        [paused]
                                («ушли после пробного»)             │
                                                                    │ вернулся
   [active] ──ушёл из группы──► [left] («ушли из активной группы») ─┘
```

Правила переходов:

| Из | В | Триггер | Побочный эффект |
|---|---|---|---|
| lead | trial | назначен пробный урок | `trialAt = now` |
| trial | active | создан `enrollment` со `status: 'active'` | стартует биллинг с `activatedAt` |
| trial | left | админ отметил «не пришёл» | попадает в KPI «Ушли после пробного» |
| active | paused | заморозка записи | списания прекращаются со дня заморозки |
| paused | active | снятие заморозки | списание за остаток месяца по факту уроков |
| active | left | уход из группы | перерасчёт за неотходенные уроки месяца |
| любой | archived | мягкое удаление | пропадает из списков, история цела |

Статус студента = максимальный по «активности» статус среди его `enrollments`.
Если хоть одна запись `active` → студент `active`.

### 2. Расписание и генерация уроков

#### Типы расписания

| `schedule.type` | Что означает | Дни |
|---|---|---|
| `even` | «Чётные дни» | недельный паттерн: вт/чт/сб |
| `odd` | «Нечётные дни» | недельный паттерн: пн/ср/пт |
| `weekdays` | По дням недели | `weekdays: [1,3,5]` = пн/ср/пт (свои дни, не привязаны к even/odd) |

`even`/`odd` — не календарная чётность числа месяца, а фиксированный
недельный паттерн (как `weekdays`, но с зашитыми днями). Даёт стабильные
~13 занятий в месяц, а не 15–16 как при календарной чётности.

#### Генерация

```js
generateLessons(group) →
  для каждой даты D от group.startDate до min(group.endDate, +3 месяца вперёд):
    если matchesSchedule(D, group.schedule) и D не в settings.holidays:
      upsert lessons/{groupId}_{yyyy-MM-dd} { status: 'planned' }
```

Генерируем скользящим окном на 3 месяца вперёд, а не на весь срок группы:
группа `I13` идёт до 01.01.2027 — это ~380 документов уроков на группу,
при 29 группах — 11 000 лишних документов.

Перегенерация запускается при: создании группы, изменении расписания,
открытии месяца в сетке посещаемости, которого ещё нет.

Изменение расписания **не трогает** уроки со `status: 'held'` и уроки в прошлом.

#### «Неделя обучения» (колонка в списке групп)

Не хранится. Это прогресс группы от старта до сегодня.

```js
const months = differenceInMonths(today, group.startDate);
const days   = differenceInDays(today, addMonths(group.startDate, months));
const weeks  = Math.round(days / 7);
// вывод: `${months} месяцев\n${weeks} недели`
```

**Проверка на данных скриншота 3 (дата съёмки — 24.07.2026):**

| Группа | Старт | Расчёт | На скриншоте |
|---|---|---|---|
| I12 | 27.10.2025 | 8 мес + 27 дн → round(3.86)=4 | 8 месяцев 4 недели ✅ |
| I13 | 01.12.2025 | 7 мес + 23 дн → round(3.29)=3 | 7 месяцев 3 недели ✅ |
| I14 | 01.11.2025 | 8 мес + 23 дн → 3 | 8 месяцев 3 недели ✅ |
| I5 | 27.10.2025 | 8 мес + 27 дн → 4 | 8 месяцев 4 недели ✅ |
| I6 | 10.06.2026 | 1 мес + 14 дн → 2 | 1 месяц 2 недели ✅ |
| I7 | 29.10.2025 | 8 мес + 25 дн → round(3.57)=4 | 8 месяцев 4 недели ✅ |
| MINI 1 | 22.06.2026 | 1 мес + 2 дн → round(0.29)=0 | 1 месяц 0 недель ✅ |

7 из 7. Округление именно `Math.round`, не `floor` и не `ceil` — `floor` ломает
I12/I7, `ceil` ломает MINI 1.

Склонения выводить через `pluralize()`: «1 месяц», «2 месяца», «8 месяцев».

### 3. Деньги

#### 3.1 Цена урока

```js
pricePerLesson = enrollment.price / group.lessonsPerMonth
```

`lessonsPerMonth` — константа центра (по умолчанию **12**), задаётся в филиале
и переопределяется на группе. Это не количество уроков в конкретном месяце
по календарю: 840 000/890 000 — фиксированная цена за 12 уроков в месяц;
если по факту в месяце 13 или 14 занятий (см. §2), лишние — бонусные, без
доплаты сверху фиксированной суммы.

Раньше константа стояла 14 (см. открытый вопрос №2 в «01 · Обзор продукта») —
выведена из скриншота 6 (240 000 за 4 урока → 60 000/урок →
840 000/60 000 = 14). Заказчик впоследствии подтвердил верное значение — **12**.

#### 3.2 Первое списание (частичный месяц)

При активации записи в середине месяца:

```js
lessonsLeft = кол-во уроков группы по расписанию в диапазоне
              [activatedAt, конец месяца]
amount      = -(pricePerLesson * lessonsLeft)
```

Запись создаётся со следующими полями:
- `date` = **1-е число месяца** (не дата активации),
- `createdAt` = фактическое время создания,
- `comment` = `"{lessonsLeft} ур."`,
- `periodFrom` = `activatedAt`, `periodTo` = конец месяца.

**Проверка на скриншоте 6:**
студент Abduqodir Jo'raev, группа R30, нечётные дни, активация 24.07.2026.
Уроки до конца июля: 25, 27, 29, 31 → 4 урока.
`4 × 60 000 = 240 000` → запись `01.07.2026 · система · −240 000 UZS · «R30 4 ур. 24.07.2026—31.07.2026»` ✅
Оплата `24.07.2026 · оплата · +100 000 UZS · Click` ✅
Баланс: `−240 000 + 100 000 = −140 000` ✅ (совпадает с бейджем `-140 000 UZS`)

#### 3.3 Ежемесячное списание

1-го числа каждого месяца по каждой активной записи создаётся списание
на полную месячную цену: `amount = -enrollment.price`, `comment = "Оплата за {месяц}"`.

Не списываем, если: `enrollment.status !== 'active'`, запись заморожена на весь
месяц, или уже существует документ `charge_{enrollmentId}_{YYYY-MM}`.

#### 3.4 Биллинг-ран (без бэкенда)

Cloud Functions не используем (план Spark). Начисление запускается с клиента:

```
При входе пользователя с ролью owner/accountant:
  читаем billingRuns/{branchId}_{текущий месяц}
  если документа нет и сегодня >= 1-е число:
     показываем в топбаре баннер «Начислить за июль 2026» + кнопка «Начислить»
  по нажатию:
     1) создаём billingRuns/{...} { status: 'running', startedAt }
     2) выбираем enrollments: branchId, status == 'active', lastChargedMonth != текущий
     3) пачками по 400 операций через writeBatch:
        - set(transactions/charge_{enrollmentId}_{month})   // идемпотентно
        - update(students/{id}.balance, increment(amount))
        - set(monthlyBalances/{studentId}_{month}, merge)
        - update(enrollments/{id}.lastChargedMonth = month)
     4) billingRuns.status = 'done', processed = N
  показываем результат: «Начислено 148 студентам на 124 320 000 UZS»
```

Идемпотентность держится на ID документа списания. Двойной клик, обновление
страницы, параллельный запуск с двух компьютеров — списание всё равно одно.

#### 3.5 Заморозка и уход

**Заморозка** (`paused`): списания не создаются за месяцы, полностью попавшие
в интервал `[pausedFrom, pausedTo]`. Частично замороженный месяц считается
по формуле частичного месяца — по фактическим урокам вне заморозки.

**Уход из группы** в середине месяца: создаётся `type: 'correction'` на возврат
стоимости неотходенных уроков:

```js
amount = +(pricePerLesson * lessonsAfterLeaveDate)
comment = "Перерасчёт при уходе"
```

#### 3.6 Баланс

```
balance = Σ transactions.amount по студенту
```

Хранится денормализованно в `students.balance` и обновляется `increment()`
в той же batch-операции, что и транзакция. Отдельная админ-кнопка
«Пересчитать баланс» пересуммирует все транзакции студента и чинит расхождение.

Должник: `status === 'active' && balance < 0`.

Цвет точки рядом с именем студента в списке группы (скриншот 4):
`balance >= 0` → зелёная, `balance < 0` → красная.

#### 3.7 Скидка

`enrollment.price` может быть меньше `group.price`. Скидка не отдельная сущность,
а сохранённая разница: `discountPercent = round((1 - price/group.price) * 100)`.

Из скриншотов: группа I14 — 890 000; студент в R30 — 840 000.

### 4. Посещаемость

#### Сетка

Строки — студенты группы, колонки — уроки выбранного месяца.

| Ситуация | Что рисуем |
|---|---|
| Урок в прошлом, отметка есть | бейдж `Был` (teal) / `Нет` (blue) |
| Урок в прошлом, отметки нет | пустой бейдж-заглушка, кликом ставится отметка |
| Урок сегодня или в будущем | пустой круг, клик разрешён только для «сегодня» |
| Студент добавлен позже даты урока | **пустая ячейка**, ничего не рисуем |

Последнее правило важно: на скриншоте 4 у студента Jaloliddin Xasanov отметки
начинаются с 16 июля, до этого — пустота, а не «Нет».

Условие: рисуем ячейку, только если `lesson.date >= enrollment.activatedAt`.

#### Отметка

Клик по ячейке циклически переключает: `—` → `Был` → `Нет` → `—`.
Каждый клик — немедленная запись в Firestore (оптимистичный апдейт + откат при ошибке).
Ctrl+клик по заголовку колонки — «отметить всех присутствующими».

Отмечать может: `admin`, `owner`, и учитель — только свои группы и только за
последние 7 дней. Более старые даты правит админ.

Посещаемость **не влияет** на списания: деньги считаются по расписанию, а не по
факту прихода (см. открытый вопрос №4 в `01-overview.md`).

| Оплатили в текущем месяце | 134 | уникальные `studentId` в `transactions`: `type == 'payment' && month == текущий` |
| Ушли из активной группы | 53 | `enrollments`: `leftAt` в периоде, предыдущий статус `active`, уникальные студенты |
| Ушли после пробного периода | 8 | `students`: `trialAt != null && status == 'left' && никогда не был active`, `leftAt` в периоде |

Период для двух последних карточек — текущий календарный год, значение задаётся
в настройках филиала (`settings.churnPeriod`: `month | quarter | year`).

Сходимость на данных скриншота: 134 оплатили + 16 должников = 150 ≈ 148 активных.
Расхождение нормально — часть оплативших могла уйти в течение месяца.

#### График выручки

Линейный график, ось X — месяцы от первого платежа центра (сент. 2017) до текущего,
ось Y — `Σ transactions.amount` где `type == 'payment'`, сгруппировано по `month`.

Не считать это по всей коллекции транзакций каждый раз. Держим агрегат
`monthlyRevenue/{branchId}_{YYYY-MM}` и обновляем `increment()` при каждой оплате.
При первом запуске — разовый скрипт пересчёта.

#### Финансы: «Всего платежей» и «Чистая прибыль»

```
Всего платежей  = Σ payment.amount за период фильтра
Чистая прибыль  = Всего платежей − расходы за период
```

Модуля расходов в MVP нет, поэтому обе цифры равны — ровно как на скриншоте 5
(98 554 000 UZS и там, и там). Блок «Details» раскрывает разбивку по методам оплаты.

позвонить (лог звонка), записать на пробный, конвертировать в студента, отказ (с причиной).
Канбан-воронка — P2.

Простые списки с CRUD. Курс: название, цена по умолчанию, длительность, цвет.
Кабинет: название, вместимость. Нельзя архивировать курс/кабинет, если он

### Общие правила интерфейса

- **Загрузка** — скелетоны в форме контента, не спиннер по центру.
- **Пусто** — `EmptyState`: иконка, одна строка «Пока нет групп», кнопка действия.
- **Ошибка** — «Не удалось загрузить. Проверьте соединение» + «Повторить».
- **Разрушающее действие** — `ConfirmDialog` с явным названием объекта в тексте.
- **Успех** — toast справа сверху, 3 секунды, с кнопкой «Отменить» там, где отмена возможна.
- **Формы** — валидация на blur, ошибка под полем красным, кнопка сохранения
  блокируется на время запроса и показывает спиннер.
- **Таблицы** — горизонтальный скролл с липкой первой колонкой, без обрезания данных.
- **Все списки** — состояние фильтров в URL.
- **Клавиатура** — Esc закрывает модалку, Enter сабмитит, видимый фокус.

## 05 · Дизайн-система

Цель — попасть в визуал референса, а не придумать новый. Скриншоты в
`docs/reference/` — эталон. Всё ниже снято с них.

Стиль: светлый корпоративный интерфейс. Серый фон, белые карточки с мягкими
тенями, тёмно-синий как единственный «тяжёлый» цвет для действий и чисел,
оранжевый — только для иконок и графиков. Цвета не смешиваем: оранжевая кнопка
или синяя иконка статистики — ошибка.

| `navy` | `#22406B` | кнопки, активный пункт меню, акцент вкладок |
| `navy-hover` | `#1A3357` | hover кнопок |
