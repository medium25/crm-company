## Где данные лежат

- `scripts/_phase2_raw_page1.txt` … `_phase2_raw_page25.txt` — сырые строки платежей, ВСЕ 25 страниц
  (формат: `дата\tимя\tсумма UZS\tметод\tучитель\tгруппа\tсоздатель\tdatetime_создания`,
  таб-разделитель, без заголовка).
- `scripts/_migrate_phase2_payments.mjs` — скрипт импорта: читает все `_phase2_raw_pageN.txt`,
  сопоставляет имя с активным студентом (точное совпадение fullName среди `isArchived==false`),
  несовпавшие (архив/лиды/не наши) — отбрасывает, пишет transactions в Firestore.
  Список файлов для чтения — переменная `files` в начале `main()`, теперь `1..25` (обновлено).

## Сбор страниц 17-25 — ГОТОВО

Собраны через встроенный Browser pane (Chrome-расширение не было подключено в той сессии,
пользователь залогинился в modme вручную в Browser pane). Метод, который сработал:

1. Finance → All payments, фильтр Date from = `01.02.2026`, Date to = `31.07.2026`.
   Датапикер игнорирует form_input — клики по `‹`/`›` в календарном виджете сработали.
2. Пагинация — через JS: `document.querySelectorAll('li.number')`, клик по нужной странице;
   если номера нет в видимых — клик по `li.btn-quicknext` (элемент el-pager "…"), с ожиданием
   ~500-800мс между кликами (Vue-рендер асинхронный).
3. Извлечение — на этой странице таблица — это `table.table-payments`, начисто читается через
   `tbody tr → td.innerText` (7 колонок: date, name, sum, method, teacher, group, "creator\ndatetime"
   — creator и datetime внутри одной td, разделены `\n`, split по нему).

## Решения, принятые пользователем по ходу

- Активных/архивных/удалённых студентов — переносить только активных (146), архив не трогать.
- История платежей — **весь период** (пользователь сначала просил 6 мес, потом снял ограничение,
  идём до конца — 25 страниц = вся история от 01.02.2026 до конца).
- История посещаемости — только последние 2 месяца (Phase 3, ещё не начат).
- Каждый большой шаг (запись в боевую БД) — требует явного "да"/"запускай" в чате, не делается
  автоматически.
