# Создание приложений без знания программирования
### Полный алгоритм + шаблон, по которому ученик собирает приложение сам

Этот документ — костяк курса. Он ведёт человека от пустого экрана до готового приложения, которое открывается на iPhone, Android и Mac. Ученик на каждом шаге понимает, **что** он делает и **зачем**. Единственное, чего он не пишет руками — это сам код.

---

## 0. Модель целиком (прочитать один раз, чтобы видеть картину)

Логика простая и всегда одна и та же:

**Ты описываешь → Claude пишет код (обычный сайт) → GitHub бесплатно хранит файлы и выдаёт ссылку → ссылка открывается в любом браузере → «Добавить на экран Домой» превращает сайт в приложение → если нужно сохранять данные или вход по пользователям, это берёт на себя Firebase.**

«Приложение для Mac / iPhone / Android» — это не три разные разработки. Это **один веб-сайт**, который устанавливается как приложение (технология PWA). Поэтому учим один путь, а не три.

### Роли инструментов

| Инструмент | Что это простыми словами | Что мы там делаем |
|---|---|---|
| **Claude Desktop (вкладка Code)** | Приложение с ИИ, который пишет код по твоему заданию | Описываем приложение в папке проекта, получаем и правим файлы |
| **GitHub** | Хранилище файлов + бесплатный хостинг | Заливаем файлы, включаем Pages, получаем ссылку на сайт |
| **Firebase** | База данных + система входа | Сохраняем данные, делаем личные аккаунты (когда это нужно) |
| **Браузер** | Chrome / Safari | Здесь открывается приложение и отсюда же «ставится» на телефон |

**Важное правило курса:** Firebase нужен НЕ всегда. Если приложение просто что-то показывает или считает и данные не обязаны сохраняться между визитами — хватает GitHub, и на этом всё. Firebase подключаем только когда нужно **сохранять данные** или делать **личные кабинеты**.

## 1. Регистрации (делается один раз перед стартом)

Пройти до начала работы. Рядом — что именно мы будем делать в каждом сервисе.

| Сервис | Ссылка | Зачем | Стоимость |
|---|---|---|---|
| **Claude (платный план)** | claude.ai | Даёт доступ к Claude Code, который пишет код | **Нужен платный план** (Pro / Max). **Бесплатный план Claude Code не даёт** — это надо сказать ученику сразу |
| **GitHub** | github.com | Хранит файлы и бесплатно публикует сайт | Бесплатно |
| **Google-аккаунт → Firebase** | console.firebase.google.com | База данных и вход пользователей | Бесплатно (план Spark) |

> ⚠️ **Пункт, который чаще всего забывают:** Claude Code работает только на платной подписке Claude. Ученик, который придёт с бесплатным аккаунтом, застрянет на первом же шаге. Это нужно проговорить до продажи курса.

## 2. Установка (делается один раз)

Раньше приходилось ставить кучу программ вручную. Сейчас достаточно одного приложения — **Claude Desktop**. Отдельная установка Claude Code через терминал не нужна: вкладка **Code** внутри приложения работает на том же движке — это тот же Claude Code, только с окном, деревом файлов и наглядным просмотром изменений (для новичка удобнее). Всё, что терминал даёт сверху (флаги запуска, параллельные агенты, автоматизация) — инструменты для программистов, в нашем сценарии не нужны.

### Установка (Mac и Windows одинаково)

1. Скачать настольное приложение **Claude Desktop** с сайта Anthropic (claude.ai, кнопка Download) под свою систему.
2. Установить, запустить, войти своим аккаунтом Claude (с активной подпиской).
3. Открыть вкладку **Code** — это и есть Claude Code. Здесь создаём папку проекта, пишем задание, получаем и правим готовые файлы.

> ⚠️ **Только для Windows:** перед первым открытием вкладки Code нужно установить **Git for Windows** (git-scm.com) и перезапустить приложение — без него вкладка Code не заработает. На Mac доустанавливать ничего не нужно.

### Git — желательно, но для старта не обязательно

Claude Code точнее работает в папке с Git (видит историю правок), а встроенный в приложение терминал умеет заливать файлы в GitHub командой `git push`. На Mac Git обычно уже установлен. Для базового пути курса (заливка файлов в GitHub перетаскиванием) Git не требуется — можно подключить позже.

### Итог этапа — чек-лист «готов к работе»
- [ ] Claude Desktop установлен, вход выполнен (подписка активна)
- [ ] Вкладка **Code** открывается
- [ ] (Только Windows) Git for Windows установлен
- [ ] Получается создать/открыть папку проекта во вкладке Code

## 3. ШАБЛОН ТЗ — сердце курса

Это главная ценность. Ученик не пишет Claude «сделай мне приложение», а **отвечает на правильные вопросы** и вставляет ответы. От качества этого шаблона зависит результат.

### 3.1. Единый шаблон задания (вопросы + ответы)

Ученик вписывает ответы прямо в шаблон и целиком отправляет его Claude как задание. Подсказки в скобках объясняют, что даёт каждый выбор, — так ученик понимает, что делает.

```
Ты — мой разработчик. Собери веб-приложение по заданию ниже.

1. ЗАДАЧА — одним предложением, что решает приложение:
   [ответ]

2. ПОЛЬЗОВАТЕЛИ — кто им пользуется (только я / команда / клиенты / кто угодно по ссылке):
   [ответ]

3. ЧТО ДЕЛАЕТ ПОЛЬЗОВАТЕЛЬ — 3–7 главных действий:
   - [действие]
   - [действие]
   - [действие]

4. ДАННЫЕ ДЛЯ ХРАНЕНИЯ — перечисли поля:
   [ответ]

5. ДАННЫЕ СОХРАНЯЮТСЯ МЕЖДУ ВИЗИТАМИ? (да → нужен Firebase; нет → хватит GitHub):
   [да / нет]

6. ДАННЫЕ У КАЖДОГО СВОИ ИЛИ ОБЩИЕ? (свои → нужен вход, Firebase Authentication):
   [свои / общие]

7. ЭКРАНЫ — какие страницы нужны (например: главная-список; добавление; профиль):
   [ответ]

8. ДИЗАЙН:
   - Стиль / референс: [ответ] (фото приложу отдельно)
   - Тема: [тёмная / светлая]
   - Ощущение шрифта: [строгий / дружелюбный / минимализм]
   - Приоритет — мобильная версия (mobile-first)

9. ЛИЧНЫЕ АККАУНТЫ (логин)? (да → Firebase Authentication):
   [да / нет]

10. УСТАНОВКА КАК ПРИЛОЖЕНИЕ на телефон/рабочий стол? (да → делаем PWA, этап 7):
    [да / нет]

11. РАБОТА БЕЗ ИНТЕРНЕТА? (да → добавим офлайн-режим):
    [да / нет]

Сначала собери рабочий локальный прототип — я посмотрю и внесу правки.
Пока НЕ подключай базу данных и вход: сделаем это отдельным шагом.
```

### 3.2. Технические правила вывода (всегда добавлять в конце)

Это решает проблему «лишних папок и хешей», из-за которых мусор копится в GitHub:

```
ПРАВИЛА КОДА:
- Собери как обычный статический сайт: чистый HTML, CSS, JavaScript.
- Без сборщиков (Vite, webpack), без Node-зависимостей, без node_modules.
- Все файлы — плоским списком в корне: index.html, style.css, script.js.
  Никаких вложенных папок и никаких файлов со случайными хешами в имени (типа index-a3f8b2.js).
- index.html обязательно в корне.
- Внешние библиотеки подключай через CDN — обычными <script>-тегами. Пользоваться ими можно свободно (Firebase, Tailwind, Chart.js, карты и т.д.) — ограничение касается только сборщиков и node_modules, а не функций.
```

## 4. Сборка локально с Claude

1. **Создать папку проекта**, назвать именем проекта (например `icon-tasks`).
2. Открыть эту папку во вкладке **Code** (Claude Desktop) как проект.
3. **Вставить заполненный шаблон** из пункта 3.1 (+ технические правила 3.2, + приложить фото-референсы).
4. Claude соберёт **локальный прототип**. Посмотреть его проще всего во встроенной панели предпросмотра вкладки Code (Browser) — HTML открывается прямо там. При желании файл `index.html` можно открыть и в обычном браузере (Chrome/Safari).
5. **Правки словами:** «сделай кнопки крупнее», «поменяй цвет шапки на тёмно-синий», «добавь поле даты». Прикладывать скриншоты — Claude их видит.
6. Когда всё нравится — попросить: **«Сохрани финальную версию по техническим правилам: плоские статические файлы в корне, без папок и хешей».**

Результат этапа: в папке лежат готовые файлы (`index.html` и рядом стили/скрипт), которые можно залить в GitHub.

## 5. Публикация на GitHub Pages — получаем ссылку

Здесь сайт становится доступен по ссылке в интернете.

1. Зайти на **github.com** → кнопка **New** (новый репозиторий).
2. Задать имя, выбрать **Public**, нажать **Create repository**.
3. **Залить файлы:** на странице репозитория → **Add file → Upload files** → перетащить ВСЕ файлы из папки → внизу **Commit changes**.
   > `index.html` должен оказаться в корне репозитория, а не внутри подпапки.
4. Открыть **Settings** (вкладка репозитория) → слева **Pages**.
5. В блоке **Source** выбрать **Deploy from a branch** → **Branch: main**, папка **/(root)** → **Save**.
6. Подождать **2–3 минуты**, обновить страницу Pages.
7. Наверху появится ссылка вида
   ```
   https://твойлогин.github.io/имя-репозитория/
   ```
8. Открыть её — сайт в интернете. Этой ссылкой уже можно делиться.

> **Способ для новичка** — перетаскивание файлов (шаг 3). Когда освоишься, тот же результат делается быстрее командой `git push` прямо из Claude Code — это можно дать как продвинутый уровень.

## 6. База данных (Firebase) — когда нужно сохранять данные

Подключаем, только если в Блоке C был ответ «данные должны сохраняться».

### Правильный порядок (моя единственная рекомендация — не мучить учеников вариантами)

**Сначала собрать и отладить приложение локально → затем настроить Firebase и вшить его в код → затем залить на GitHub → в конце добавить домен в разрешённые (см. этап 6.4).** Так не приходится ничего переделывать.

### 6.1. Создать проект Firebase
1. **console.firebase.google.com** → **Add project** → задать имя → Analytics можно **выключить** → **Create project**.

### 6.2. Зарегистрировать веб-приложение и забрать ключи
2. На главной проекта нажать иконку **</>** (Web) → задать название → **Register app**.
3. Firebase покажет блок **firebaseConfig** (apiKey, projectId и т.д.) — **скопировать целиком**.

### 6.3. Включить базу и вшить в код
4. Слева **Build → Firestore Database → Create database** → выбрать регион → создать.
5. Отдать Claude ключи и попросить: **«Подключи Firebase Firestore к приложению через CDN, вот мой firebaseConfig: [вставить]. Сохраняй/читай данные из Firestore»**. Claude впишет код.
6. Проверить локально, что данные сохраняются, затем перезалить файлы в GitHub (этап 5, шаг 3).

> **Про безопасность — важный момент, который пугает новичков:** ключи `firebaseConfig` **не являются секретом**, их нормально держать в коде на публичном GitHub. Данные защищают не спрятанные ключи, а **правила Firestore** (следующий пункт). Оставить базу в открытом «test mode» — вот это настоящая ошибка.

## 7. Личный прогресс у каждого пользователя (вход + правила)

Твой пункт «чтобы у каждого был свой прогресс». Делается это НЕ просто «меняем правила», а связкой **вход (Authentication) + правила (Rules)**.

### 7.1. Включить вход
1. Слева **Build → Authentication → Get started**.
2. Включить способ входа: **Email/Password** (проще всего) или **Google**.

### 7.2. Хранить данные под ID пользователя
3. Попросить Claude: **«Добавь вход через Firebase Authentication (Email/Password). Данные каждого пользователя сохраняй под его uid, чтобы каждый видел только свой прогресс. Вот мой firebaseConfig: [вставить]»**.

### 7.3. Закрыть правила Firestore
4. В **Firestore → Rules** поставить правило: доступ к своим данным только у их владельца. Пример:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{userId}/{document=**} {
         allow read, write: if request.auth != null && request.auth.uid == userId;
       }
     }
   }
   ```
   *(Claude сгенерирует правило под твою структуру — правила тоже можно у него попросить.)*

### 7.4. ⚠️ Разрешить домен (шаг, который все забывают)
5. После публикации на GitHub Pages вход на живом сайте **не заработает**, пока не добавишь адрес сайта в белый список:
   **Firebase → Authentication → Settings → Authorized domains → Add domain →** вставить `твойлогин.github.io`.

Без этого шага логин работает локально, но падает на реальной ссылке. Это самая частая «непонятная» ошибка.

## 8. Превращаем сайт в приложение (iPhone / Android / Mac)

Это тот самый шаг, который делает из ссылки «приложение с иконкой». Технология называется **PWA**.

### Что просим у Claude
```
Сделай приложение устанавливаемым (PWA):
- добавь manifest.json (имя, иконки, display: standalone, цвета темы и фона);
- добавь иконки нужных размеров (192px, 512px, apple-touch-icon 180px);
- добавь мета-теги для iOS (полноэкранный режим, статус-бар);
- добавь service worker для базового офлайн-режима.
```
После этого перезалить файлы в GitHub.

### Как ученик устанавливает приложение

| Устройство | Как поставить |
|---|---|
| **iPhone (Safari)** | Кнопка «Поделиться» → **На экран «Домой»**. *(На iPhone установка не всплывает сама — этому шагу нужно научить.)* |
| **Android (Chrome)** | Меню (⋮) → **Установить приложение** / Добавить на главный экран |
| **Mac / ПК (Chrome, Edge)** | Значок установки в адресной строке справа → **Установить** |

Результат: отдельная иконка, запуск без адресной строки браузера — выглядит как обычное приложение.

## 9. Обновление приложения (цикл после запуска)

Приложение живое — его можно менять в любой момент:

1. Открыть папку в Claude Code, описать правку словами.
2. Перезалить изменённые файлы в GitHub (перетаскиванием или `git push`).
3. GitHub Pages сам пересоберёт сайт за ~1–2 минуты.
4. Обновить страницу — правки на месте.

> Если добавляли service worker (офлайн), у пользователей может показываться старая версия из кэша. Решение: при обновлении менять номер версии в service worker — попросить об этом Claude.

## 10. Чек-лист перед тем, как отдать/продать приложение

- [ ] `index.html` лежит в корне репозитория
- [ ] Репозиторий **Public**, Pages включён, ссылка открывается
- [ ] На телефоне открывается и ставится на экран «Домой»
- [ ] Если есть вход: домен `github.io` добавлен в **Authorized domains**
- [ ] Правила Firestore **закрыты** (никакого открытого test mode)
- [ ] Проверено на реальном телефоне, а не только на компьютере

## 11. Частые ошибки новичков (и что говорить)

| Симптом | Причина | Решение |
|---|---|---|
| Белый/пустой экран на Pages | `index.html` не в корне или выбрана не та папка в Pages | Проверить корень репозитория и настройку Source в Pages |
| Данные видит любой / любой их перезаписывает | Осталась база в открытом test mode | Настроить правила Firestore (этап 7.3) |
| Вход не работает на живом сайте, а локально работал | Домен не в белом списке | Добавить `github.io` в Authorized domains (этап 7.4) |
| В GitHub копятся файлы с хешами и папки | Собирали через сборщик (Vite/webpack) | Дать технические правила из п. 3.2 — плоские статические файлы |
| Вкладка Code не открывается (Windows) | Не установлен Git for Windows | Установить с git-scm.com и перезапустить приложение |
| «У меня не запускается Claude Code» | Бесплатный план Claude | Нужна подписка Pro/Max (этап 1) |

## Как это ложится в структуру курса

Логичное деление на модули:

1. **Вводный** — модель целиком (этап 0) + регистрации (этап 1).
2. **Установка** — один раз настраиваем инструменты (этап 2).
3. **Главный навык** — шаблон ТЗ и правильные вопросы (этап 3). Здесь основная ценность.
4. **Первое приложение** — сборка + публикация без базы (этапы 4–5). Быстрый результат = мотивация.
5. **С данными** — Firebase и сохранение (этап 6).
6. **С аккаунтами** — вход и личный прогресс (этап 7).
7. **Установка как приложение** — PWA (этап 8).
8. **Жизнь после запуска** — обновления, чек-лист, ошибки (этапы 9–11).

Порядок модулей повторяет реальный путь: сначала быстрый видимый результат (живой сайт), потом усложнение по мере необходимости.
